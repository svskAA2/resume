How it Works?
Isolated Method Variables: All data required to process a request is stored in local variables on the thread’s execution stack (local to the method), 
not in the bean’s instance variables.

No Shared Mutability: Since the bean lacks internal fields that are written to or modified during execution, 
there is nothing for concurrent threads to "collide" over.

Independent Execution: Every incoming HTTP request (or client call) gets its own isolated thread. 
Because the bean acts merely as a set of instructions rather than a container for user data, threads do not interfere with one another.

🌊 STREAM:
   Sequence of elements
   Functional operations
   Lazy evaluation
   One-time use
   NOT a data structure

🎯 OPERATIONS:
   Source → Intermediate → Terminal

🌱 CREATION:
   collection.stream()
   Stream.of(elements)
   Arrays.stream(arr)
   IntStream.range(start, end)
   Stream.iterate/generate

🔧 INTERMEDIATE (lazy, return Stream):
   filter(Predicate)
   map(Function)
   flatMap(Function)
   sorted(), sorted(Comparator)
   distinct()
   limit(n), skip(n)
   peek(Consumer)
   takeWhile, dropWhile (Java 9+)

🏁 TERMINAL (return result):
   collect(Collector)
   count()
   forEach(Consumer)
   reduce(...)
   findFirst, findAny
   anyMatch, allMatch, noneMatch
   max, min
   toArray()

📦 COLLECTORS:
   toList(), toSet(), toMap()
   joining(", ")
   counting()
   groupingBy(...)
   partitioningBy(...)
   summarizingDouble(...)
   averagingDouble(...)
   summingInt(...)
   mapping(...)

⚡ PARALLEL:
   parallelStream() or .parallel()
   ForkJoinPool internally
   Use for large data, CPU-intensive
   Avoid for small data, I/O, side effects

🚨 PITFALLS:
   1. Stream reuse → IllegalStateException
   2. Side effects → unpredictable
   3. Forgetting terminal op → no execution
   4. toMap with duplicate keys
   5. Null handling

💎 BEST PRACTICES:
   1. Use method references
   2. Filter before map
   3. Use primitive streams (IntStream)
   4. Avoid side effects
   5. Be careful with parallel
   6. Filter early for performance
   7. Use Collectors fully
   8. Don't reuse streams
